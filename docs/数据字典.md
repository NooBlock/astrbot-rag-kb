# 数据字典

本页定义 `corpora/` 下每个语料目录的数据契约：文件构成、字段含义、编码与内容要求、校验规则和版本约定。自己写构建脚本或接入其他向量库时，以本页为准。

## 一、目录与文件构成

```
corpora/<NN_slug>/
├─ chunks.jsonl     # 必需：预切块语料，一行一条
├─ manifest.json    # 必需：知识库元信息，导入时读取
└─ README.md        # 必需（仓库约定）：来源、许可、构建方法、已知局限
```

- `<NN_slug>`：两位数字前缀 + 英文短名，例如 `01_cheer_terms`。`tools/build_kbs.py` 只扫描 `corpora/` 下**前两位是数字**的目录，新增库必须遵守此命名。
- 目录内不得放 `raw/` 原始数据（仓库不发布第三方原始抓取内容）；不在 `corpora/` 内放 README 之外的说明文件。
- 公共状态文件：`corpora/_state/imported.json`，由导入脚本自动维护（见第五节），不属于语料契约。

## 二、`chunks.jsonl`

### 2.1 格式

- 编码 **UTF-8 无 BOM**，换行 `\n`（LF 优先；CRLF 也能被解析，但不建议）。
- **每行一个 JSON 对象**，字段固定为：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 是 | **语料内自增编号**，从 0 或 1 起、连续、唯一。仅用于排序与追溯；导入 AstrBot 时只使用 `text`，不使用 `id` |
| `text` | string | 是 | 已切好、可直接 embedding 的完整片段；**必须自包含** |

- 空行会被跳过；但交付文件不应包含空行。
- 每个库的 `id` 起点不同（本仓 01/04/05 从 1 起，02/03 从 0 起），**同一库内必须连续唯一**；跨库不要求一致。
- 不要附加其他字段（如 `source`/`score`）；需要来源信息写进 `manifest.json` 或 `README.md`。读取方应容忍未来新增字段。

示例（真实条目，来自 01 库）：

```json
{"id": 2, "text": "【词条】半场开香槟\n【释义】指在比赛中取得暂时领先就得意忘形，最终导致失败的行为。\n【详解】在竞技比赛中，一方因为优势过大而得意忘形，最终被人翻盘的情况"}
```

### 2.2 内容要求

| 要求 | 说明 |
| --- | --- |
| **自包含** | 单独被检索出来也能读懂。不能只有「666」「哈哈」这种裸词；要带词条名、语境或对话上下文 |
| **长度** | 建议 **80–800 字符**。本仓 01 库最短 49 字符（词条本身极短但含释义，仍自包含）；硬上限由校验器控制，默认 **1200 字符** |
| **去重** | 完全相同的 `text` 只保留一条（本仓 5 个库重复数均为 0）。近义/近似重复不强制去除，但同一库内应避免成段复制 |
| **清洗** | 不含 HTML 标签、Markdown 表格分隔行、零宽字符、控制字符；连续空白压缩；emoji 可以保留 |
| **切分** | 不要把整篇长文塞成一条（语义会被稀释）；长文按主题或句末标点拆成多条，续片在开头重复词条名/主题名 |
| **安全** | 不含真实姓名、电话、QQ/微信、住址等个人信息；不含 API Key、密码、Token；不整段搬运受版权保护的原文（本仓为清洗/摘要/结构化后的二次整理） |
| **语言** | 中文为主，允许少量英文与 emoji；`manifest.language` 标注语种 |

### 2.3 各库组织方式（供参考）

| 库 | `text` 结构 |
| --- | --- |
| 01 网络流行语释义库 | `【词条】…\n【释义】…\n【例句】…（可选）\n【详解】…` |
| 02 网梗对话风格库 | `对话：\n用户：…\n回复：…`，每 chunk 约 4 组对话 |
| 03 弱智吧语料库 | `弱智吧神提问（主题）：\n1. …` 或 `弱智吧问答（…）：\n问：…\n答：…` |
| 04 V吧黑话库 | `【词条】…\n【释义】…\n【出处/语境】…\n【用法示例】…（可选）` |
| 05 地狱笑话库 | `【地狱笑话】…\n【类型】…\n【使用提示】…` |

统一原则：**检索命中后，模型不需要再查其他数据就能理解这段文本在说什么。**

## 三、`manifest.json`

UTF-8 无 BOM 的单个 JSON 对象。本仓 5 个库实际字段一致，如下（**以此为准**，旧版 SPEC 中的示例字段可能过时）：

| 字段 | 类型 | 必需性 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `kb_name` | string | **必需**（校验器强制） | AstrBot 知识库显示名，也是配置 `kb_names` 的匹配依据；**改名等于新建库** | `"网络流行语释义库"` |
| `description` | string | **必需**（校验器强制） | 一句话说明，显示在 WebUI；导入脚本会在内容变化时同步 | `"中文网络流行语词条释义库：…"` |
| `emoji` | string | **必需**（校验器强制） | 单个 emoji，显示在知识库列表；只改它不会自动同步到已建库 | `"🗣️"` |
| `source_url` | string | **必需**（校验器强制） | 上游来源 URL；多个来源用 ` ; ` 分隔（本仓 03 库即如此） | `"https://github.com/SCUNLP/Buzzword"` |
| `num_chunks` | integer | **必需**（校验器强制） | 必须**严格等于** `chunks.jsonl` 的非空行数 | `1219` |
| `source_license` | string | 建议必填 | 上游许可状态说明；会被导入状态记录，用于合规追溯 | `"上游未提供 LICENSE；研究/自用…"` |
| `language` | string | 建议 | 语种标签 | `"zh-CN"` |
| `built_at` | string | 建议 | ISO 8601 时间，带时区偏移 | `"2026-10-26T02:59:32+08:00"` |
| `builder` | string | 建议 | 构建者/构建工具标识（便于追溯） | `"corpus-cheer"` |
| `notes` | string | 建议 | 构建方式、抽样策略、已清洗掉什么、已知局限；单行字符串 | `"全量使用 1183 个词条…"` |

约束：

- 允许出现上表之外的附加字段（读取方应忽略），用于未来扩展；
- 不允许包含本机绝对路径、凭据、个人联系方式；来源必须是可公开访问的 URL；
- `manifest.json` 的编码同样是 UTF-8 无 BOM，JSON 不允许注释与尾逗号。

示例（字段值有删节）：

```json
{
  "kb_name": "网络流行语释义库",
  "description": "中文网络流行语词条释义库：每条含【词条】【释义】【例句】【详解】…",
  "emoji": "🗣️",
  "source_url": "https://github.com/SCUNLP/Buzzword",
  "source_license": "上游未提供 LICENSE；研究/自用，再分发需授权并引用论文",
  "language": "zh-CN",
  "num_chunks": 1219,
  "built_at": "2026-10-26T02:59:32+08:00",
  "builder": "corpus-cheer",
  "notes": "全量使用 1183 个词条…（详见 corpora/01_cheer_terms/README.md）"
}
```

## 四、校验规则（`tools/validate_corpus.py`）

命令：

```bash
python tools/validate_corpus.py corpora/01_cheer_terms   # 单个目录
python tools/validate_corpus.py --all corpora            # 批量
```

校验器逐项检查（与 `tools/validate_corpus.py` 实现一致）：

| # | 检查 | 不通过时 |
| --- | --- | --- |
| 1 | `chunks.jsonl` 与 `manifest.json` 都存在 | 立即 FAIL 返回 |
| 2 | 每个非空行是合法 JSON 且为对象 | 记录「第 N 行 JSON 非法 / 不是对象」 |
| 3 | `text` 是字符串且非空 | 记录「第 N 行 text 为空」 |
| 4 | `len(text)` ≤ `--max-text`（默认 **1200**） | 记录「text 过长」 |
| 5 | 完全重复的 `text` 数为 0 | 记录重复条数 |
| 6 | 有效条数 ≥ `--min`（默认 **50**） | 记录「少于下限」 |
| 7 | `manifest.json` 含 `kb_name`、`description`、`emoji`、`source_url`、`num_chunks` | 记录缺失字段 |
| 8 | `manifest.num_chunks` == 实际条数 | 记录不一致 |

校验器**不检查**：`id` 是否存在/连续（工具不依赖 id）、BOM（但带 BOM 的首行通常会直接导致 JSON 解析失败）、`source_license` 等建议字段、内容安全。`--max-text` 与 `--min` 可按需调整，但调整后请同步更新本页与库 README。

输出示例：

```text
目录: corpora/01_cheer_terms
条数: 1219
长度: min=49 avg=325 max=891
kb_name: '网络流行语释义库'

[OK] 校验通过
```

## 五、状态文件 `corpora/_state/imported.json`

由 `build_kbs.py` 写入，用于幂等导入（不是语料契约，但换机/排查时会看到）。结构：

```json
{
  "01_cheer_terms": {
    "kb_id": "<运行中实例的 UUID>",
    "kb_name": "网络流行语释义库",
    "source_url": "https://github.com/SCUNLP/Buzzword",
    "source_license": "…",
    "num_chunks": 1219,
    "num_docs": 2,
    "elapsed_seconds": 78.1,
    "completed_at": "2026-10-26T03:10:49+08:00",
    "sha256": "<chunks.jsonl 的 SHA-256>"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `kb_id` | 该实例中知识库的 ID；换实例后无意义 |
| `num_chunks` / `num_docs` | 导入的 chunk 数与文档分片数（脚本按 800 条/文档分片） |
| `elapsed_seconds` / `completed_at` | 导入耗时（含 embedding）与完成时间 |
| `sha256` | 导入时 `chunks.jsonl` 的哈希；与当前文件比较决定是否跳过/重建 |

注意：该文件只记录**本机状态**，不含凭据。新实例上不存在也能正常导入；但**不要在库已有数据时删除它**（脚本会当作未导入而重复导入，`chunk_count` 校验失败，需 `--force` 重建），也不要手工伪造哈希。

## 六、版本与兼容约定

- **当前为 schema v1**：没有 `schema_version` 字段。约定为「`chunks.jsonl` 两字段 + `manifest.json` 上表字段」。
- 新增**可选**字段（如 `schema_version`、`source_fetched_at`）属于向后兼容变更：读取方忽略未知字段，工具照常工作。
- 任何**破坏性**变更（字段改名、`chunks.jsonl` 结构变化、去掉 `num_chunks` 等）必须：① 在 `manifest.json` 增加 `"schema_version": "2"`；② 更新 `SPEC.md`、本页与各库 README；③ 在仓库 Release/提交说明里写迁移方法。
- 版本追溯以 `manifest.built_at` + `chunks.jsonl` 的 SHA-256 为准（见下表）；不要用文件修改时间。

## 八、自己新增语料的最小检查清单

- [ ] 目录名 `NN_slug`；
- [ ] `chunks.jsonl`：UTF-8 无 BOM、一行一 JSON、`id` 连续、`text` 自包含且 80–800 字符；
- [ ] `manifest.json`：`kb_name` 稳定、`num_chunks` 与实际一致、`source_url` 可访问、`source_license` 如实填写；
- [ ] `README.md`：来源、构造方法、已知局限、许可状态；
- [ ] `python tools/validate_corpus.py <目录>` 通过；
- [ ] 需要入库时 `python tools/build_kbs.py --config <ASTRBOT_DATA>/cmd_config.json --only <目录>`，并用 `verify_kbs.py` 冒烟。
