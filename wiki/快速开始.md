# 快速开始

目标：从零到「机器人在对话中真正能用上这 5 个知识库」。全程不需要原作者的机器环境。

## 0. 前置条件

| 项 | 要求 | 检查方式 |
| --- | --- | --- |
| AstrBot | **v4.29.3**（本项目验证版本；内置知识库自 v3.5.13 起提供，导入脚本依赖 v4.18.0 起的 `/api/v1`） | WebUI 版本号或启动日志 |
| Python | **3.12**（AstrBot 要求 `>=3.12`） | `python -V` |
| 嵌入模型 | 任一 OpenAI 兼容的 embedding 服务（云 API 或本地 Ollama 均可） | WebUI →「模型提供商 → 嵌入」可用 |
| 磁盘 | 几十 MB（语料文本 + 向量索引，索引大小取决于维度和 embedding 服务） | — |
| 网络 | 能访问 AstrBot WebUI 与 embedding 服务 | — |

**AstrBot 从哪来**：从 [AstrBot 仓库](https://github.com/AstrBotDevs/AstrBot) 或 [官方文档](https://docs.astrbot.app/) 选择一种部署方式（桌面版、CLI、Docker、面板均可），装好并启动到 WebUI 能打开为止。本文默认 WebUI 地址为 `http://127.0.0.1:6185`。

> 导入时每个 chunk 的文本都会发给你的 embedding 服务。本项目语料均为公开数据，但如果你换了别的语料，请按数据的敏感程度选择本地 embedding。

## 1. 获取语料

```bash
git clone https://github.com/NooBlock/astrbot-rag-kb.git
cd astrbot-rag-kb
```

没有 git 的话，在 GitHub 页面点 `Code → Download ZIP` 解压即可。目录应包含 `corpora/`、`tools/`、`docs/`、`wiki/`；`corpora/01_cheer_terms/chunks.jsonl` 等文件存在即正常。

> 原始抓取数据 `raw/` 不随仓库发布，导入不需要它。

## 2. 校验语料格式（推荐，30 秒）

```bash
python tools/validate_corpus.py --all corpora
```

也可以只校验一个库：

```bash
python tools/validate_corpus.py corpora/01_cheer_terms
```

正常输出每个库的 `条数`、`长度: min/avg/max`、`kb_name` 和 `[OK] 校验通过`。Windows 控制台若中文乱码，先执行：

```powershell
$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"
```

## 3. 在 AstrBot 中配置嵌入模型

1. 启动 AstrBot，打开 WebUI（默认 `http://127.0.0.1:6185`）。
2. 侧边栏 → **模型提供商** → **嵌入** 标签 → **新增**。
3. 以 OpenAI 兼容服务为例填写：

   | 字段 | 示例值 | 说明 |
   | --- | --- | --- |
   | API Key | `<YOUR_TOKEN>` | 你的 embedding 服务 Key |
   | API 基础地址 | `https://api.siliconflow.cn/v1` | 以你的服务商为准 |
   | 模型 | `Qwen/Qwen3-Embedding-8B` | 本项目快照使用的模型 |
   | 向量维度 | `1024` | 必须与模型实际输出一致 |

4. 保存并确认该提供商「可用」。
5. 记下提供商的 **id**（常见为 `openai_embedding`）：脚本建库时用它。可在 WebUI 提供商详情、或 `astrbot/data/cmd_config.json` 的 `provider` 数组里看到。

> 维度不是随便填的：1024 维的库只能用 1024 维的模型查询。换模型 = 换向量空间 = 必须重建知识库，见[维护与更新 § 更换 embedding 模型的后果](维护与更新.md#更换-embedding-模型的后果)。

## 4. 建库并导入

两条路径，任选其一：

| 方式 | 适合 | 是否保持「一条 chunk = 一条语料」 |
| --- | --- | --- |
| **脚本导入**（`tools/build_kbs.py`） | 全量 5 个库、可重复执行、批量 | ✅ 预切块原样导入 |
| WebUI 手动上传 | 只建一两个库、不想碰命令行 | ❌ 会被 AstrBot 按 512 字符重新分块 |

### 4.1 脚本导入（推荐）

原理：脚本读取 AstrBot 的 `cmd_config.json`，用其中的 `dashboard.jwt_secret` 在本机签发短期 JWT，调用 WebUI 的 `/api/v1` 知识库接口，**不需要 WebUI 密码**。

先准备依赖：

```bash
python -m pip install -r tools/requirements.txt
```

**关于 embedding provider id**：脚本新建知识库时默认使用 `openai_embedding`（`tools/kb_client.py` 中 `create_kb()` 的默认参数）。如果你的提供商 id 不是它，任选一种处理：

1. **推荐**：先在 WebUI 按 `manifest.json` 的 `kb_name` 建好同名空知识库（例如「网络流行语释义库」），并选好你的 embedding 提供商；脚本会按名称找到已有库，只做导入，不再关心 provider id。
2. 或者修改 `tools/kb_client.py` 里 `create_kb()` 的 `embedding_provider_id` 默认值，改成你的提供商 id（可在 WebUI 提供商详情或 `cmd_config.json` 的 `provider` 数组里查到）。

> `--config` 未指定时，脚本尝试读取当前目录下的 `astrbot/data/cmd_config.json`；大多数情况请显式传 `--config`。

然后执行（`--config` 指向 AstrBot 数据目录下的 `cmd_config.json`；也可用环境变量 `ASTRBOT_CONFIG`）：

```bash
python tools/build_kbs.py --config /path/to/astrbot/data/cmd_config.json
```

Windows PowerShell（用 AstrBot 的 venv）：

```powershell
$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"
& "C:\path\to\astrbot\.venv\Scripts\python.exe" `
  "C:\path\to\astrbot-rag-kb\tools\build_kbs.py" `
  --config "C:\path\to\astrbot\data\cmd_config.json"
```

常用参数：

```bash
python tools/build_kbs.py --config <ASTRBOT_DATA>/cmd_config.json --create-only          # 只创建知识库，不导入
python tools/build_kbs.py --config <ASTRBOT_DATA>/cmd_config.json --only 01_cheer_terms  # 只处理指定目录（逗号分隔可多选）
python tools/build_kbs.py --config <ASTRBOT_DATA>/cmd_config.json --force                # 忽略状态记录，删库重建
```

其他约定：

- `--root` 默认是仓库下的 `corpora/` 目录（即语料根目录本身）；语料放在别处时用 `--root` 指定。
- 服务端地址默认 `http://127.0.0.1:6185/api/v1`；AstrBot 端口不同或不在本机时，用环境变量 `ASTRBOT_BASE_URL` 覆盖（例如 `http://127.0.0.1:6185/api/v1`）。
- `--config` 指向的文件**包含 `dashboard.jwt_secret` 等敏感信息**，只在本机使用，不要提交到任何仓库或发给别人。

脚本行为：按 `manifest.json` 的 `kb_name` 查找知识库，没有就创建 → 分片调用预切块导入接口 → 轮询任务 → 用 stats 校验 chunk 数 → 写入 `corpora/_state/imported.json`（记录条数与 `chunks.jsonl` 的 sha256）。**同一份语料重复执行会跳过**，内容变了才会删库重建，因此可以放心反复跑。

预期输出（每库一行，最后是 JSON 汇总）：

```text
[01_cheer_terms] kb_name='网络流行语释义库' chunks=1219
  -> 校验 doc_count=2 chunk_count=1219 / 期望 1219
...
```

### 4.2 WebUI 手动导入

只想用网页操作，见[导入到 AstrBot § A. WebUI 手动导入](导入到%20AstrBot.md#a-webui-手动导入)。注意：**`chunks.jsonl` 不是 AstrBot 支持的上传格式**，网页上传会重新分块，预切块效果会打折扣。

## 5. 验证

```bash
python tools/verify_kbs.py --config <ASTRBOT_DATA>/cmd_config.json
```

会打印每个知识库的 `docs` / `chunks`，并用 5 个查询做检索冒烟（如「尊嘟假嘟是什么意思？」「什么是独轮车？」）。也可以指定查询：

```bash
python tools/verify_kbs.py --config <ASTRBOT_DATA>/cmd_config.json \
  --query "地狱笑话为什么好笑" --query "aewt 是什么"
```

对照期望值：

| 知识库 | chunk 数 |
| --- | ---: |
| 🗣️ 网络流行语释义库 | 1219 |
| 💬 网梗对话风格库 | 1804 |
| 🧠 弱智吧语料库 | 1320 |
| 🎭 V吧黑话库 | 120 |
| 💀 地狱笑话库 | 81 |

另外在 WebUI 打开任一知识库 → **知识库检索** 标签，输入一个语料里确实有的问题，确认能召回片段。

## 6. 让知识库参与对话（关键，别漏）

建好库不等于会用到。**两个开关都要设**：

1. WebUI → **配置文件** → 选中机器人实际使用的配置 → **AI → 能力 → 知识库**；
2. **知识库列表**（`kb_names`）勾选要暴露的库；
3. 打开 **Agentic 知识库检索**（`kb_agentic_mode`，需要模型支持函数调用）；
4. 保存配置。

为什么两个都要：Agentic 模式下检索是一个工具（`astr_kb_search`），工具内部仍按 `kb_names`（或会话级 kb_ids）决定检索范围；`kb_names` 为空时工具只会返回 “No relevant knowledge found.”。

然后在聊天里试：

```text
先查一下知识库：尊嘟假嘟是什么意思？
```

详细的模式取舍、会话级优先级和推荐配置见[导入到 AstrBot § C. 如何让知识库真正参与对话](导入到%20AstrBot.md#c-如何让知识库真正参与对话)。

## 常见失败

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `Connection refused` / 连接超时 | AstrBot 没启动，或端口不是 6185 | 确认 WebUI 能打开，设置 `ASTRBOT_BASE_URL` |
| `401 Invalid token` / `Token expired` | `jwt_secret` 不匹配、系统时钟偏差、配置被重置 | 核对 `--config` 指向的文件，重开 AstrBot，见 [FAQ](FAQ.md#jwt-expired) |
| 建库报「向量维度不匹配」 | 库里记录的维度与 embedding 服务输出不一致 | 用正确维度重建，见[维护与更新](维护与更新.md) |
| `chunk_count` 与期望不一致 | 上次导入失败留下孤儿 chunk，或用了会被重新分块的上传方式 | 对该库加 `--force` 重建 |
| 控制台中文乱码 | Windows 控制台是 GBK | `$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"` |
| 模型说「没有找到相关知识」 | 只开了 Agentic 但 `kb_names` 为空，或会话级 kb_ids 覆盖 | 检查两处配置，见 [FAQ](FAQ.md#retrieval-miss) |
