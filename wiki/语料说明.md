# 语料说明

本仓库包含 **5 个知识库、合计 4544 条 chunk**，全部构建于 2026-10-26（+08:00）。所有数字来自各库 `manifest.json`、导入状态记录与产物实测（`chunks.jsonl` 逐行统计），未做估算。

先给结论：

- 语料是**公开数据的二次整理**，不是人工编纂的词典；释义可能过时、语气语料难免带冒犯性。
- 5 个库的用途不同：01 用来「准确解释」，02/03/04 用来「学习语气与圈层语境」，05 只作为**受控的风格噪声**。
- 上游许可多数未声明，**仅建议学习/自用**，见[许可与合规](许可与合规.md)。

## 分层设计

之所以不把所有梗塞进一个知识库，是因为不同语料的检索目标冲突：释义要**准确、短、自包含**；对话语料要**保留口语和上下文**；社区语料要**贴住圈层黑话**。混在一起会让 embedding 语义互相稀释，检索结果既不像词典也不像聊天。

| 层 | 作用 | 对应库 |
| --- | --- | --- |
| 核心释义层 | 回答「X 是什么意思」 | 🗣️ 网络流行语释义库 |
| 风格语料层 | 学「用户抛梗—回复接梗」的语气 | 💬 网梗对话风格库 |
| 社区风格层 | 特定社区的黑话与反差幽默 | 🧠 弱智吧语料库 / 🎭 V吧黑话库 / 💀 地狱笑话库 |

## 🗣️ 网络流行语释义库（`01_cheer_terms`）

| 项 | 内容 |
| --- | --- |
| 定位 | 「X 是什么意思」的精确释义库；覆盖 B 站/微博/抖音等平台的高频热词与梗 |
| 层 | 核心释义层 |
| chunk 数 | **1219**（上游 1183 个词条，28 个超长词条拆成续片，共多出 36 条） |
| 来源 | [SCUNLP/Buzzword](https://github.com/SCUNLP/Buzzword)（四川大学 SCUNLP，ACL 2025 配套数据集） |
| 直接数据 | `data/data.py`（构建时 5,214,058 字节，Python 字面量 `rawdata = {词条: {...}}`） |
| 许可 | 上游**未提供 LICENSE**（GitHub API `license` 为空），研究数据集，未声明开放许可 → 仅自用；再分发需授权并引用论文 |
| 构建者 / 时间 | `corpus-cheer` / 2026-10-26T02:59:32+08:00 |

**原始数据形态**：一个 Python 字典，1183 个键（词条），值里包含 `definition`（释义）、`examples`（例句列表）、`ground_truth`（详解），以及 6 个模型生成的 `*_KEY` 释义和 `*_score` 互评分数。

**清洗与抽样**：

- **全量使用**，未抽样；
- 只取 `definition` / `examples` / `ground_truth` 三个字段；**不使用** `*_KEY`（上游打分显示含明显事实错误）与 `*_score`（非语料内容）；
- 去零宽字符与控制字符、压缩空白；把上游用裸尖括号写的书名（如 `<长河浪花集>`）规范为《长河浪花集》，其余尖括号换 `‹ ›`，避免被误判成 HTML；
- 单条 ≤ 900 字符则 1 词条 = 1 chunk；> 900 字符的 28 个词条按句末标点拆成 2–4 片，每片开头重复 `【词条】X（续）`；
- 完全重复的 `text` 只保留一条（构建后为 0）。

**text 字段组织**（`【例句】` 仅 49 个词条非空，其余省略）：

```text
【词条】半场开香槟
【释义】指在比赛中取得暂时领先就得意忘形，最终导致失败的行为。
【详解】在竞技比赛中，一方因为优势过大而得意忘形，最终被人翻盘的情况
```

**质量评估**：格式统一、自包含、适合精确检索；释义来自上游研究标注，不是人工复核词典；4 个词条极短（49–76 字符），仍保留「词条 + 释义」结构；近义词未合并（如「粉切黑 / 粉红切开都是黑 / 粉红的切开来里面都是黑的」各自成条），检索时可能命中多条近似内容，属预期。

**已知局限**：个别词条的流行时间、出处可能有偏差或已过时；词条以 2010s–2020s 的 B 站/ACG/微博语境为主，**2024 年后的新梗覆盖有限**；未收录模型生成释义，因此没有额外角度或类比。

**敏感边界**：网络流行语里天然有低俗、贬义、攻击性词条（如谐音骂人、嘲讽向）。本库把它们当**释义对象**，应只用于「解释这个词是什么意思」，不要让模型主动用这些词攻击对话对象；对未成年人场景建议整库不启用或加关键词过滤。

**清洗与抽样**：读取全部 8245 组，取 user/assistant 首轮；剔除约 **1017 组**（空串、纯符号/纯表情、控制字符、URL、微信/QQ 等联系方式与广告、≥150 字的通用 AI 长回答或 ≥100 字且带「建议/推荐/首先/1）2）」条列结构的书面回答、完全重复对），保留 **7228 组**并**全量使用**，不按热度或长度筛选，避免丢失小众梗。

**text 字段组织**（不改写原文语气，emoji 保留）：

```text
对话：
用户：周末团建真的必须参加吗
回复：包的，不然领导又要记小本本了

用户：同事当面吹领导彩虹屁也太明显了吧

```

**质量评估**：真实评论区口语、接梗自然，适合让模型「学口气」；chunk 长度 102–588 字符，远小于上限；未做书面化改写。

**敏感边界**：含夸张自嘲、损友互怼、少量冒犯性表达。作为**风格参考**使用，不要让模型照搬攻击性内容；不要据此生成针对具体人的贬损。

## 通用使用建议

1. **先看来源再看内容**：每个库的 `README.md` 有更细的清洗与抽样说明，`manifest.json` 有准确条数与来源 URL。
2. **释义库教事实，风格库教语气**：不要让风格语料回答事实问题，也不要用释义库去「学语气」。
3. **05 地狱笑话默认关闭或加过滤**；04 黑称词条不主动复述；03 避免照搬黑色玩笑；01 只作解释、不作攻击。
4. **静态快照**：所有库都是 2026-10 的快照，新梗覆盖不到。要长期运营请按[维护与更新](维护与更新.md)搭「动态更新层」。
